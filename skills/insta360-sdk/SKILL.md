# Insta360 postprocessing

Turn preserved camera originals into verified stitched assets, then finish the requested photographic edit. This skill covers the supplied **MediaSDK 3.1.5** and **InsMetaDataSDK 2.0.2** public APIs, plus a verified **Insta360 Studio 5.9.10** photo DNG export route. It does not operate cameras. All functions are indexed; runtime verification is narrower and explicitly recorded in [verification](references/verification.md).

**Tested SDK environments:** Ubuntu 22.04 amd64 containers on Apple Silicon and native x86-64 Linux. CPU/Mesa produces ordinary INSP panoramas; NVIDIA compute exposure also enables AI stitching in the tested Linux setup. Omit optional SDK file logging and capture stderr: file logging triggered teardown crashes in controlled tests. See [runtime boundaries](references/runtime.md#tested-platform) before selecting a GPU path. Studio is a separate native macOS application; its DNG export does not establish native macOS SDK support.

## Choose the relevant path

- **Find or qualify input:** [Originals and representation](references/inputs.md). Search `Arashi Vision` as well as `Insta360`; native files may use the former make. Use original bytes, not thumbnails, and record source identity/checksum.
- **Stitch INSP with the SDK:** [runtime and helper commands](references/runtime.md), then the photo procedure below. Helpers use the user's locally supplied SDK; the skill does not distribute proprietary binaries or models.
- **Preserve a RAW-derived editing route:** qualify paired originals, then use [Studio full-sphere DNG export](references/runtime.md#studio-full-sphere-dng-export) and the [editing handoff](references/photo-edit-handoff.md). The SDK's direct One RS DNG path failed acceptance, including a successful call that rendered the wrong scene.
- **Look up any SDK function, enum, callback, parameter, video export, or frame extraction:** [complete MediaSDK reference](references/media-sdk.md). Its realtime section is an API completeness reference, not a camera-control workflow.
- **Inspect native gyro, GPS, exposure, timestamps, model, or firmware:** [MetadataSDK reference](references/metadata-sdk.md). Parse success and optional stream presence are separate facts.
- **Finish in the AI photo editor:** [photo-edit handoff](references/photo-edit-handoff.md). Apply the available `photo-edit-master` for artistic direction and `rapidraw-mcp` for its supported editing operations when those are relevant and installed.

## Photo procedure

1. **Classify from pixels and metadata.** Distinguish native dual fisheye, stitched full-sphere equirectangular, flat reframe, and RAW. A 2:1 image can still contain two fisheye circles. Retain the native trailer, RAW companions, capture grouping, and original hashes. Do not stitch an ordinary flat JPEG just because its make says Insta360.
2. **Resolve prerequisites for the chosen route.** Studio uses its native photo export UI. For SDK work, read the installed headers and helper/runtime version. Linux ELF cannot run natively on macOS. The offline Ubuntu container has qualified CPU/Mesa and a Linux NVIDIA-compute/Mesa combination; native macOS SDK execution and full NVIDIA graphics remain unqualified. `GetMediaFileInfo` returned true with zero fields for the tested INSP, so use decoded dimensions and MetadataSDK to corroborate it.
3. **Make a baseline.** For RAW work, export a full-sphere Studio DNG with its processing choices recorded. For the SDK JPEG route, start with one native INSP, optical-flow stitching, automatic accessory detection, and explicit full-sphere output dimensions. Probe native gyro for every proposed single-frame input: bracket companions can parse successfully yet lack their own gyro stream. Enable FlowState only with qualified source gyro and inspect the horizon; choose a verified gyro-bearing capture member when appropriate rather than silently disabling stabilization after a failure. Begin with a small review render, then export chosen settings at justified final resolution. Preserve the baseline and record exact inputs/options/runtime/output.
4. **Treat brackets deliberately.** Supply only distinct frames from the same capture with verified exposure variation and matching camera/geometry; a nearby filename, timestamp or count alone does not establish a bracket. One input means a single photo; exactly two is invalid; the current official API guide says three or more automatically invoke HDR fusion. Do not combine a RAW/JPEG pair as a bracket or send an unrelated batch in one call. The three-INSP bracket is tested. Some camera HDR files are already merged. DNG is documented as an API input, but direct One RS DNG and DNG HDR failed acceptance here. Use the separate Studio route when available. Compare a single DNG with its exact single INSP companion; a three-INSP HDR result changes exposure count and cannot isolate RAW processing.
5. **Choose changes from the image.** Compare template/optical-flow/dynamic seams where relevant. All 11 global controls are available; their integers are SDK-relative, not exposure stops or Kelvin. ColorPlus and denoise need matching model files. Inspect effects before combining them. AI stitching returned an all-black JPEG without GPU access, despite true `Stitch()`. The tested GPU-visible Linux container produced the actual scene; its AI model selected CUDA even with nominal CPU options. Qualify device visibility and inspect the output rather than treating those options as proof of CPU AI inference. Cooling-shell detection produced unchanged pixels on the tested bare-camera file, not a validated accessory correction.
6. **Verify bytes and pixels.** Check the process exit separately from `Stitch()` or callback JSON, output existence, full decode, dimensions, blank pixels, source-loading/model logs, and correspondence with the actual source scene. A direct DNG call with FlowState off returned exit 0 but rendered a diagnostic texture after a CFA decode failure. Optional SDK file logging has produced `ok:true` and valid pixels before exits 134/139 during teardown. Omit `--log-dir`, retain redirected stderr, and use a fresh bounded job; this avoided the observed container failures but is not a universal crash fix. Preserve a nonzero-exit result as failed execution even when its pixels decode. Never promote existing pixels to success merely because they decode. Run `verify_image.py`, then visually inspect the actual image, horizon, seams at both longitude boundaries, poles/nadir, faces/near objects, ghosting, highlights, noise and texture. A successful decoder or file size is insufficient. Matched comparisons require the same input, projection, orientation, and dimensions. For video, additionally check output duration, fps, codec/bit depth and audio and inspect representative frames; read the video workflow before running.
7. **Deliver or hand off.** Keep source files and sidecars unchanged. Follow the [two-branch handoff](references/photo-edit-handoff.md): preserve the full sphere through editing and final GPano verification, or choose an angle with `sphere_photo.py reframe` before editing a normal photograph. For a developed RGB16 TIFF, explicitly request `--output-format tiff16` to retain precision. Use the master editing skill for image-specific direction and the current RapidRAW skill for sessions, revisions and export. Pass isolated derivatives with source/recipe provenance; preserve the source collection. Tested SDK JPEGs lacked embedded ICC and GPano markers: verify colour handling and projection metadata at the delivery boundary, and do not claim a spherical viewer or colour profile is correct just from the filename. Record incomplete features separately from accepted output.

## Execution details that matter

The supplied `media_tool.cc` calls every public `ImageStitcher` operation and all seven global MediaSDK functions across its `image` and `info` modes. It implements template selection directly, rejects duplicate inputs and existing output entries, and returns failure for false stitches/missing files or unusable media-info dimensions. Its JSON `ok` reports SDK/file completion before process teardown, not clean exit or visual approval; use [verify_image.py](scripts/verify_image.py) afterward. Do not run concurrent jobs targeting the same output path.

`metadata_probe.cc` calls all nine parser operations and reports each stream's boolean/count separately. Its JSON omits serial/GPS coordinate arrays by default, while preserving exact timestamp integers as strings. SDK diagnostics go to stderr. Use current source timestamps and types; the public metadata headers contain conflicting or absent unit descriptions.

Prefer explicit paths and a bounded process per job. On crash/timeout/partial output, inspect receipts/files first and choose a fresh output path for a retry. The native SDK has no durable photo job/session/undo protocol. Save recipes and results externally; do not invent RapidRAW-style revisions or masks for this SDK.
